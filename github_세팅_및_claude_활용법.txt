GitHub CLI 설치 & Claude Code로 GitHub 작업하는 방법
작성일: 2026-07-28
================================================================================


■ 왜 gh CLI가 필요한가
--------------------------------------------------------------------------------
git 은 "내 컴퓨터 안에서 버전 관리"만 한다.
github.com 에 저장소를 만들거나, 로그인하거나, PR을 올리는 것은 git의 기능이 아니다.
그걸 터미널에서 하게 해주는 게 gh (GitHub CLI) 다.

  git  →  로컬 버전 관리 (init, add, commit)
  gh   →  GitHub 서비스 조작 (저장소 생성, 인증, PR, 이슈)


================================================================================
1단계 — gh CLI 설치
================================================================================

Windows에서는 winget으로 한 줄이면 된다.

    winget install --id GitHub.cli -e --source winget --accept-package-agreements --accept-source-agreements

설치 확인:

    gh --version

※ 설치 직후에는 기존에 열어둔 터미널에 PATH가 반영되지 않는다.
   gh 를 못 찾는다고 나오면 터미널을 새로 열 것.

※ 설치 경로 (PATH가 계속 안 잡힐 때 직접 호출용)
   "C:\Program Files\GitHub CLI\gh.exe"


================================================================================
2단계 — 로그인 (반드시 본인이 직접)
================================================================================

    gh auth login

프롬프트 선택 순서:
  1) GitHub.com
  2) HTTPS
  3) Yes  (Git 작업에 GitHub 자격 증명 사용)
  4) Login with a web browser
     → 화면에 8자리 코드가 뜸 → Enter 누르면 브라우저 열림 → 코드 입력 → 승인

로그인 상태 확인:

    gh auth status


★ 중요 ★
이 단계는 Claude에게 시키면 안 되고, 시킬 수도 없다. 이유는 두 가지.
  - 대화형 프롬프트라 Claude가 쓰는 비대화형 셸에서는 입력이 불가능해 멈춘다.
  - 비밀번호/토큰 같은 자격 증명은 Claude가 대신 입력하지 않는 것이 원칙이다.
로그인만 직접 해두면, 그 뒤로는 전부 Claude에게 맡길 수 있다.


================================================================================
3단계 — 로컬 폴더를 GitHub 저장소로 올리기
================================================================================

폴더 안에서 순서대로:

    git init -b main
    git add -A
    git commit -m "커밋 메시지"

그 다음 GitHub에 저장소를 만들면서 한 번에 푸시:

    gh repo create potato --public --source=. --remote=origin --push

옵션 의미:
    potato        저장소 이름
    --public      공개 저장소 (비공개로 하려면 --private)
    --source=.    현재 폴더를 올림
    --remote=origin  원격 이름을 origin으로 등록
    --push        만들자마자 바로 푸시

이후 수정사항 올릴 때:

    git add -A
    git commit -m "무엇을 바꿨는지"
    git push


================================================================================
Claude Code에게 요청하는 방법 (문구 예시)
================================================================================

■ 처음 올릴 때
--------------------------------------------------------------------------------
  "이 폴더를 git 저장소로 만들고 커밋한 뒤,
   GitHub에 <이름> 저장소를 public으로 만들어서 푸시해줘."

  → Claude가 init / add / commit / gh repo create --push 까지 처리한다.
     단, gh auth login 이 미리 되어 있어야 한다.


■ 수정사항 반영할 때
--------------------------------------------------------------------------------
  "변경된 내용 확인하고, 적절한 커밋 메시지로 커밋해서 푸시해줘."

  → 커밋 메시지까지 알아서 써준다. 메시지 규칙이 있으면 미리 말해둘 것.


■ 상태가 꼬였을 때
--------------------------------------------------------------------------------
  "지금 git 상태 확인해서 뭐가 문제인지 설명해줘. 아직 고치지는 말고."

  → 먼저 진단만 시키고, 설명을 읽은 뒤 고치라고 하는 편이 안전하다.


■ 되돌리고 싶을 때
--------------------------------------------------------------------------------
  "직전 커밋을 되돌리고 싶은데, 방법 몇 가지랑 각각 뭐가 사라지는지 알려줘."

  → reset / revert 는 되돌리기 어려우므로 실행 전에 설명부터 요구할 것.


================================================================================
주의사항 / 실제로 겪은 문제
================================================================================

1. 공개 저장소(public)에 올리기 전 내용 확인
   회사 자료, 계정 정보, 거래처명, API 키가 섞여 있지 않은지 반드시 확인.
   한 번 푸시되면 검색엔진에 색인될 수 있고, 나중에 지워도 남을 수 있다.
   애매하면 --private 로 만들고 나중에 GitHub 설정에서 public으로 바꾸면 된다.

2. 한글 경로 문제  ← 실제로 겪음
   경로에 한글이 들어가면 (예: Desktop\정성호\개인\github)
   PowerShell에서 cd / git -C 가 "경로를 찾을 수 없다"고 실패하는 경우가 있다.

   더 위험한 건, cd 가 실패했는데도 뒤이은 git init 이 그냥 실행되어
   엉뚱한 위치(홈 디렉터리 등)에 저장소가 만들어진다는 점이다.

   대응:
   - 여러 명령을 && 없이 ; 로 이어붙이지 말 것 (앞이 실패해도 뒤가 실행됨)
   - git init 직후 반드시 "Initialized ... in <경로>" 출력의 경로를 눈으로 확인
   - 가능하면 영문 경로에 저장소를 두는 것이 안전

3. .gitignore 를 먼저 만들 것
   엑셀 임시파일(~$로 시작), 로그, 가상환경 폴더 등이 딸려 올라가지 않게
   커밋 전에 .gitignore 를 만들어두면 좋다.

       ~$*
       *.log
       .venv/
       __pycache__/

새 노트북에서 이 저장소 이어서 작업하기 — 세팅 체크리스트
작성일: 2026-07-28
저장소: https://github.com/potato-account/potato
================================================================================


■ 먼저 이해할 것 — 무엇이 따라오고 무엇이 안 따라오는가
--------------------------------------------------------------------------------

  [ 저장소에 담겨 따라오는 것 ]
    - 파일 내용
    - 커밋 이력 (누가 언제 무엇을 바꿨는지)
    - CLAUDE.md 같은 규칙 파일

  [ 기기마다 새로 해야 하는 것 ]
    - git 설치
    - gh CLI 설치
    - gh auth login  (GitHub 로그인 — 계정이 아니라 '기기'에 인증이 붙는다)
    - Claude Code 설치

즉, 파일을 다운받는다고 세팅이 끝나는 게 아니다.
로그인과 도구 설치는 새 기기에서 한 번씩 다시 해줘야 한다.


================================================================================
세팅 3단계
================================================================================

--------------------------------------------------------------------------------
1단계. 저장소 내려받기
--------------------------------------------------------------------------------

작업할 폴더로 이동한 뒤:

    git clone https://github.com/potato-account/potato.git

potato 폴더가 생기고 그 안에 파일과 커밋 이력이 전부 들어온다.

※ git이 없다면 먼저 설치
    winget install --id Git.Git -e --source winget

※ 참고: 웹에서 Download ZIP 으로 받는 방법도 있지만, 그러면 git 이력이
   딸려오지 않아 이후 커밋/푸시가 안 된다. 반드시 clone 할 것.


--------------------------------------------------------------------------------
2단계. gh CLI 설치 + 로그인
--------------------------------------------------------------------------------

설치:

    winget install --id GitHub.cli -e --source winget --accept-package-agreements --accept-source-agreements

설치 후 터미널을 새로 열고 로그인:

    gh auth login

  선택 순서: GitHub.com → HTTPS → Yes → Login with a web browser
  8자리 코드가 뜨면 브라우저에 입력하고 승인

확인:

    gh auth status
    → "Logged in to github.com account potato-account" 나오면 성공

★ 이 단계는 반드시 본인이 직접. Claude에게 시킬 수 없다.
   (대화형 입력이 필요하고, 자격 증명은 Claude가 대신 다루지 않는다)


--------------------------------------------------------------------------------
3단계. 그 폴더에서 Claude Code 실행
--------------------------------------------------------------------------------

clone 받은 potato 폴더를 작업 폴더로 지정해서 Claude Code를 연다.
폴더가 맞게 잡혔는지 확인하려면 이렇게 물어보면 된다:

    "지금 작업 폴더 어디고 git 상태 어떤지 알려줘"


================================================================================
세팅 끝난 뒤 — 이렇게 쓰면 된다
================================================================================

파일을 고치거나 추가한 뒤:

    "potato 폴더 변경사항 커밋해서 푸시해줘"

이 한 마디면 Claude가 git diff로 실제 변경분을 확인하고,
커밋 메시지를 작성해서 커밋한 뒤 푸시까지 처리한다.

그 밖의 요청 예시:

    "지금 git 상태 확인해서 뭐가 바뀌었는지 설명해줘"
    "최근 커밋 5개 요약해줘"
    "직전 커밋 되돌리는 방법이랑 각각 뭐가 사라지는지 알려줘"


================================================================================
주의 — 커밋 컨벤션은 아직 정해져 있지 않다
================================================================================

"커밋해줘" 라고만 하면 Claude가 무난한 메시지를 알아서 쓰긴 하지만,
정해진 규칙을 따르는 것은 아니다. 세션이 바뀌면 스타일이 달라질 수 있다.

일관된 규칙을 원한다면 저장소 루트에 CLAUDE.md 파일을 만들어
규칙을 적어두어야 한다. Claude Code는 이 파일을 세션 시작 시 자동으로 읽는다.
(이 txt 파일은 사람이 읽는 안내문일 뿐, 자동으로 적용되지 않는다)

CLAUDE.md 예시:

    ## 커밋 규칙
    - 형식: <타입>: <한글 요약 50자 이내>
    - 타입: feat / fix / docs / refactor / chore
    - 본문에 왜 바꿨는지 한 줄
    - 커밋 전 git diff 확인 필수

    ## 푸시 규칙
    - "커밋해줘" 요청 시 커밋까지만, 푸시는 별도 지시

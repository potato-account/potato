1. 대전제 — 저장소는 두 군데에 따로 존재한다
================================================================================

git을 쓰면 같은 저장소가 최소 두 벌 존재하게 된다.

    [로컬 저장소]  내 컴퓨터 폴더 안              ← 여기서 작업하고 커밋
    [원격 저장소]  GitHub 서버                    ← 여기에 올려서 보관/공유

중요한 건 이 둘이 실시간 동기화되지 않는다는 점이다.
파일을 고치고 커밋해도 GitHub에는 아무 일도 일어나지 않는다.
내가 push 를 해야 비로소 올라간다.

    "커밋했다"  ≠  "GitHub에 올라갔다"

이 착각이 초반에 제일 많이 하는 실수다.


================================================================================
2. origin 이란 무엇인가
================================================================================

■ 한 줄 정의
--------------------------------------------------------------------------------
    origin = 원격 저장소 주소에 붙여둔 별명(nickname)


■ 왜 별명이 필요한가
--------------------------------------------------------------------------------
원격 저장소의 실제 주소는 이렇게 길다.

    https://github.com/potato-account/potato.git

푸시할 때마다 이걸 다 칠 수는 없으니, git이 이 주소를 폴더 안에 저장해두고
"origin" 이라는 짧은 이름으로 부를 수 있게 해준다.

    git push origin main
              └── "아까 저장해둔 그 주소로" 라는 뜻

그래서 origin 은 git의 예약어나 특별한 기능이 아니다.
그냥 관례적으로 쓰는 이름일 뿐이고, 다른 이름으로 바꿔도 동작한다.
(다만 모두가 origin을 쓰므로 굳이 바꿀 이유는 없다)


■ 실제로 확인해보기
--------------------------------------------------------------------------------

    git remote -v

출력 예시:

    origin  https://github.com/potato-account/potato.git (fetch)
    origin  https://github.com/potato-account/potato.git (push)

    별명    ←────── 실제 주소 ──────→               용도
                                                (가져올 때 / 올릴 때)


■ 이 정보는 어디에 저장되나
--------------------------------------------------------------------------------
저장소 폴더 안의 숨김 폴더 .git\config 파일에 들어 있다.
즉 origin 설정은 "폴더에 붙어 있는 것"이지 계정이나 컴퓨터에 붙은 게 아니다.

    → 폴더를 통째로 복사하면 origin 설정도 따라간다
    → .git 폴더를 지우면 origin도 같이 사라진다 (그냥 일반 폴더가 됨)


================================================================================
3. clone — 원격 저장소를 통째로 가져오기
================================================================================

    git clone https://github.com/potato-account/potato.git

이 한 줄이 실제로 하는 일은 네 가지다.

    1) potato 라는 폴더를 새로 만든다
    2) 그 안에 최신 파일들을 채운다
    3) 커밋 이력 전체를 가져온다 (.git 폴더)
    4) 방금 그 주소를 origin 으로 등록한다   ★ 이게 핵심 ★

4번 덕분에 clone 받은 폴더에서는 곧바로 push / pull 이 된다.
주소를 다시 입력할 필요가 없다.


■ 자주 하는 실수
--------------------------------------------------------------------------------
  ✗ 빈 potato 폴더를 미리 만들고 그 안에서 clone
    → potato\potato 가 되어버린다.
    → clone은 "저장할 상위 폴더"(예: Desktop)에서 실행할 것.

  ✗ GitHub 웹에서 Download ZIP 으로 받기
    → 파일만 온다. .git 폴더가 없어서 커밋 이력도, origin 설정도 없다.
    → 결과적으로 push가 불가능하다. 반드시 clone 할 것.

  ✗ 이미 clone 한 폴더에 또 clone
    → clone은 최초 1회만. 이후 최신화는 git pull.

4. push / pull / fetch
================================================================================

    git push     내 로컬 커밋을 원격에 올린다        (로컬 → 원격)
    git pull     원격의 변경사항을 로컬로 가져온다    (원격 → 로컬)
    git fetch    가져오되 내 파일에 합치지는 않는다   (확인만)

pull 은 사실 fetch + merge 를 한 번에 하는 것이다.
"일단 뭐 바뀌었는지 보기만 하자" 면 fetch, "바로 반영하자" 면 pull.


■ 노트북 두 대를 오갈 때의 습관
--------------------------------------------------------------------------------
    작업 시작 전  →  git pull    (다른 기기에서 올린 것 받아오기)
    작업 끝난 후  →  git push    (내가 한 것 올리기)

이 순서를 안 지키면 양쪽에서 다른 내용을 고쳐 충돌(conflict)이 난다.

5. origin/main 이라는 표기의 의미
================================================================================

git status 를 치면 이런 게 보인다.

    ## main...origin/main

여기서 두 이름은 서로 다른 것을 가리킨다.

    main          내 컴퓨터의 main 브랜치
    origin/main   "내가 마지막으로 확인한 시점의, 원격 main 상태" 기록

origin/main 은 원격을 실시간으로 비추는 거울이 아니다.
pull 이나 fetch 를 해야 갱신되는 스냅샷이다.

자주 보게 되는 메시지:

    Your branch is ahead of 'origin/main' by 1 commit
        → 커밋은 했는데 아직 push 안 함. push 하면 해소된다.

    Your branch is behind 'origin/main' by 2 commits
        → 원격에 새 게 있는데 아직 안 받아옴. pull 하면 된다.

    Your branch and 'origin/main' have diverged
        → 양쪽에 서로 다른 커밋이 생김. 합치는 작업이 필요하다.


■ -u 옵션은 무슨 뜻인가
--------------------------------------------------------------------------------

    git push -u origin docs/commit-convention

-u 는 "이 로컬 브랜치의 짝은 origin의 이 브랜치다" 라고 연결해두는 옵션이다.
한 번 걸어두면 다음부터는 뒤를 생략하고 그냥 이렇게만 쓰면 된다.

    git push
    git pull

6. clone 과 인증은 별개다
================================================================================

여기서 혼동이 잘 생긴다.

    clone           원격 주소를 등록해준다        → 자동, 폴더에 저장됨
    gh auth login   내가 그 계정임을 증명한다      → 수동, 기기마다 필요

clone 은 "주소를 안다"까지만 해결한다. "쓸 권한이 있다"는 별개 문제다.
그래서 새 노트북에서는 clone 을 해도 로그인을 따로 해줘야 push 가 된다.

    주소 등록(clone)  +  권한 증명(auth login)  =  push 가능

인증 정보는 저장소 폴더가 아니라 그 PC 자체에 저장되므로,
저장소를 몇 개를 clone 하든 로그인은 기기당 한 번만 하면 된다.


================================================================================
7. 용어 한 줄 정리
================================================================================

    저장소(repository)   버전 관리되는 프로젝트 폴더
    로컬(local)          내 컴퓨터에 있는 쪽
    원격(remote)         GitHub 서버에 있는 쪽
    origin               원격 저장소 주소에 붙인 별명
    clone                원격 저장소를 내 컴퓨터로 통째로 복사 (최초 1회)
    커밋(commit)         변경사항을 이력으로 남기는 것 (아직 로컬에만 있음)
    push                 로컬 커밋을 원격에 올리기
    pull                 원격 변경사항을 로컬로 가져오기
    브랜치(branch)       작업을 분리하는 갈래
    main                 기준이 되는 기본 브랜치
    .git 폴더            이력과 설정이 들어 있는 숨김 폴더. 지우면 다 사라진다

■ 전체 구조
--------------------------------------------------------------------------------

  [Opus] 계획서 작성  →  PLAN.md 파일로 저장  →  [Haiku/Sonnet] 파일 읽고 그대로 실행

핵심은 계획서를 채팅으로 남기지 말고 "파일로 떨구는 것".
낮은 모델 세션은 대화 맥락이 없으므로, 파일 하나만 읽으면 전부 이해되게
자기완결적으로 작성해야 한다.


================================================================================
1단계 — 계획서 작성 (높은 모델)
================================================================================

플랜 모드(Shift+Tab 두 번)로 들어가서 아래와 같이 입력.

--------------------------------------------------------------------------------
DSD 주석 자동화에서 '유형자산 주석' 시트 생성 기능을 추가하려고 한다.

지금 바로 구현하지 말고, 다른 세션의 저성능 모델이 읽고 그대로
실행할 수 있는 실행계획서를 ./plans/PLAN_주석_유형자산.md 로 작성해라.

계획서 작성 전에 관련 코드를 먼저 다 읽고 파악할 것.

계획서 요건:
- 이 파일만 읽고도 전체 맥락이 파악되게 자기완결적으로 쓸 것
- 수정할 파일은 절대경로 + 함수명/라인 기준으로 특정할 것
- 각 단계마다 "무엇을" 이 아니라 "어떤 코드로" 까지 쓸 것
- "적절히", "필요시", "판단해서" 같은 모호한 표현 금지
- 단계마다 검증 명령어와 기대 출력 명시
- 손대면 안 되는 파일 목록 명시
--------------------------------------------------------------------------------

※ 마지막 3줄이 핵심.
   저성능 모델은 판단을 시키면 무너지고, 받아쓰기를 시키면 잘한다.

================================================================================
2단계 — 실행 (낮은 모델)
================================================================================

새 세션을 열고(맥락 오염 방지) 모델을 낮은 것으로 바꾼 뒤 아래와 같이 입력.

--------------------------------------------------------------------------------
./plans/PLAN_주석_유형자산.md 를 읽고 Step 1부터 순서대로 실행해라.

규칙:
- 계획서에 없는 파일은 절대 수정하지 마라
- 계획서와 실제 코드가 다르면 멈추고 나에게 보고해라. 임의 판단 금지
- 각 Step 끝나면 검증 명령어를 실행하고 결과를 보여줘라
- 검증 실패 시 다음 Step으로 넘어가지 말고 멈춰라
--------------------------------------------------------------------------------

※ "다르면 멈춰라"가 안전장치.
   저성능 모델의 최악 케이스는 틀린 것을 창의적으로 메꾸는 것.


================================================================================
자동화 — 슬래시 명령어 2개
================================================================================

매번 위 프롬프트를 치기 귀찮으면 명령어 파일로 만들어 둔다.
슬래시 명령어는 frontmatter에 model: 을 지정할 수 있어서 모델 전환도 자동이다.


[파일 1]  ~/.claude/commands/plandoc.md

    ---
    description: 실행계획서 작성 (실행은 하지 않음)
    argument-hint: <작업 설명>
    model: opus
    ---
    (위 1단계 프롬프트 내용 + $ARGUMENTS)


[파일 2]  ~/.claude/commands/runplan.md

    ---
    description: 실행계획서대로 실행
    argument-hint: <계획서 경로>
    model: haiku
    ---
    (위 2단계 프롬프트 내용 + $1)


[사용법]

    /plandoc DSD 주석 자동화에 유형자산 주석 시트 생성 추가
    /runplan ./plans/PLAN_주석_유형자산.md


================================================================================
주의점
================================================================================

1. 한 계획서 = 한 기능으로 쪼갤 것.
   Step 15개가 넘어가면 낮은 모델의 정확도가 급락한다.
   크면 PLAN_01, PLAN_02 로 나누고 순차 실행.

2. 탐색이 필요한 작업에는 이 방식이 맞지 않는다.
   "왜 값이 틀리지?" 같은 디버깅은 그냥 높은 모델로 할 것.
   이 패턴은 '무엇을 할지 이미 정해진' 작업 전용이다.

3. 계획서는 git에 커밋해두면 나중에 "이때 왜 이렇게 했지" 추적이 된다.
